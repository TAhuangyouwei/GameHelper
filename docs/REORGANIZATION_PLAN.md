# 分阶段整理计划

目标是在任何一个阶段都保持仓库可理解、可回退，并尽量保持当前工具入口可运行。

## 基本规则

1. 每次只解决一类问题。
2. “移动/重命名”与“逻辑重构”分开提交。
3. 第三方代码只移动和记录来源，不直接格式化或重写。
4. 不透明脚本先隔离，不尝试反混淆或运行。
5. 会覆盖 .max 的批处理脚本，必须先在测试场景副本上验证。
6. 每一步开始前保持 git status 清晰；用户自己的未提交文件不混入整理提交。

## 阶段 1：建账，不动脚本

交付内容：

- 根目录 README
- 完整脚本清单
- 当前依赖关系图
- 本整理路线图
- .max 文件的 Git LFS 规则

完成标准：文档能回答“入口在哪里、文件有什么、谁依赖谁、哪些脚本危险”。

## 阶段 2：确认身份和使用状态

逐个给脚本标记：

- 我编写并继续维护
- 我修改过的第三方脚本
- 原样下载的第三方脚本
- 项目一次性脚本
- 已废弃但需要保留
- 来源不明/暂不执行

这一阶段不需要读懂所有代码，只需要由使用者确认来源和是否仍在使用。

当前已经确认：

- HYW 是仓库作者本人的署名。
- “很喜欢乱来”不是仓库作者署名。
- AnimTools.ms、FBX批量导出.ms、查看合并导出插件.ms 是当前优先维护的三个核心工具。
- tests/test_scenes 下的 .max 场景只允许保存在本地，不得上传到公开仓库。

## 阶段 3：建立稳定加载层

先不移动脚本，新增一个统一路径与工具注册表，让 AnimTools.ms 不再在每个按钮中重复拼接路径。

预期结构：

    scripts/bootstrap/main.ms
    scripts/core/paths.ms
    scripts/core/tool_registry.ms

完成后，主入口只根据工具 ID 加载脚本。未来改变文件位置时，只修改注册表。

## 阶段 4：只移动，不重写

建议按以下顺序，每组一个提交：

1. 明确第三方工具迁入 scripts/vendor/
2. 加密/混淆文件迁入 scripts/opaque/
3. 项目专用脚本迁入 scripts/archive/project_oneoffs/
4. 面部绑定五个文件整体迁入 scripts/tools/facial/
5. 动画、蒙皮、场景、导出工具分别迁入对应目录

每移动一组，都同步更新注册表并执行入口冒烟测试。

## 阶段 5：优先加固高风险批处理

优先顺序：

1. 查看合并导出插件.ms
2. FBX批量导出.ms
3. 同步武器动画.ms
4. 保存动画.ms、合并武器.ms 等历史批处理

统一增加：

- 路径选择和配置持久化
- 文件与节点预检
- 仅预览模式
- 自动备份或另存到输出目录
- 单文件日志和错误信息
- 进度、取消和失败后状态恢复

## 阶段 6：整理公共代码

将 HYW_Scripts_Library.ms 按现有职责拆成：

    core/biped.ms
    core/material.ms
    core/model.ms
    core/scene.ms
    core/layer.ms
    core/interface.ms
    core/animation.ms
    core/skin.ms

同时把跨文件重复函数抽入对应模块，只保留一个 CGH 全局命名空间。

## 阶段 7：测试与发布

- 测试场景通过 Git LFS 管理。
- 增加空场景、缺少节点、只读文件、正常角色场景等冒烟测试。
- 最终用 MacroScript 作为安装入口。
- 发布产物放入 dist/，源码和 .mse 分开。
- 制作带明确加载顺序的 .mzp 包。

## 每个提交的检查清单

- git status 中没有混入无关文件。
- 主入口能打开。
- 本次涉及的按钮能打开对应工具。
- 没有新增盘符、用户名或绝对路径。
- 没有静默覆盖测试场景原件。
- 文档中的状态与实际文件位置一致。

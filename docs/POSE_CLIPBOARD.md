# 跨 Max 姿势剪贴板

脚本：`scripts/实用工具/动画/跨Max姿势剪贴板.ms`。独立运行，不依赖主面板。

## 使用

1. 在同一台电脑、同一 Windows 用户的两个 Max 中，各运行一次脚本。
2. 在源 Max 的目标帧选择需要复制的 Biped 部位、Bone 或变换控制器，点击“复制 Pose”。
3. 在目标 Max 切到需要粘贴的帧，点击“粘贴 Pose”。目标端按同名查找，不依赖当前选择。
4. 粘贴会在当前帧打关键帧，包含复制对象的位移。成功后可一次撤销。

撤销仍待用户实测确认：上一版仅增加 `undo on` 后，用户反馈 Ctrl+Z 仍无效。当前改为先加载 Biped 姿势集合，再单独记录姿势修改；粘贴后保留所用集合，避免立即删除原生粘贴数据可能影响撤销的情况。同一份姿势重复粘贴会复用已有集合。这是待验证的修正，不表示已确认故障根因。

工具会检测撤销记录的生成情况。未检测到时直接弹出诊断信息，请提供该弹窗；所有粘贴也会向 MAXScript Listener 输出诊断计数。记录检测通过也仍需确认实际 Ctrl+Z 效果：粘贴后点击 Max 视口按 Ctrl+Z，检查姿势和新增关键帧恢复，Ctrl+Y 检查重做。此修复不能补回旧版粘贴时未记录的撤销数据。

两个 Max 需要分别加载功能，但不需要同时打开窗口。缓存保存在 `%LOCALAPPDATA%\GameHelper\PoseClipboard.xml`，与 Max 版本无关。关闭源 Max 后，缓存仍可使用。每次复制替换上一份缓存。

## 局部姿势：手臂垂下时复制，抬起后粘贴

源端只选择要复制的手指各节，不要选择手掌、手臂或 COM，然后复制。目标端保持抬手动作，在目标帧粘贴。

Biped 已使用原生 Posture 接口，按复制时保存的部位恢复；普通 Bone 保存相对父级的变换，粘贴时结合目标父级的当前变换。预期结果是保留目标手臂和手掌姿势，恢复手指相对父级的弯曲姿势。已补充相应用例，尚待 Max 内实测。

粘贴范围由源端复制时的选择决定。当前版本不提供“复制全身后，仅粘贴目标选择”的筛选；目标端只选手指不会缩小已复制的范围。

## 范围与实现

- 面向同角色、同名、同层级、相同系统单位的场景。
- Biped 调用原生 `copyBipPosture` / `pasteBipPosture`，通过原生 `.cpy` 数据传递选中部位的姿势，不替换骨骼控制器，不加载整段 `.bip` 动画。
- 目标 Biped 的 Copy Collections 会保留已使用的 `GameHelper_...` 姿势集合；每份新复制的姿势可能增加一个集合。同一份姿势反复粘贴不会持续增加。为避免干扰撤销历史，工具不会在粘贴后立即删除集合。这些集合随场景保存，属于 Max 场景内的数据，不是额外的磁盘缓存文件。
- Biped 的局部姿势仍遵循原生姿势粘贴规则，例如共享轨道和 IK 对同一肢体其他部位的影响。不同结构、Footstep/Motion Flow 模式和特殊动画层尚不保证支持。
- Bone 和表情变换控制器使用相对父级的变换，按父到子的顺序恢复；不替换控制器。约束/表达式/IK 驱动的输出骨骼应改选对应的驱动控制器。
- 不包含 Morpher 权重、自定义属性、IK/FK 开关、动画曲线、绑定结构或蒙皮数据。
- 缺失、重名、类型或直接父级不一致时，粘贴前报错；控制器拒绝写入时取消本次粘贴。
- 缓存是 XML 数据，不会作为 MaxScript 执行；Biped 数据以 Base64 嵌在同一文件中，避免半份文件被另一进程读取。

## 验证

当前交付为待实测版本：批处理启动未完成，尚未取得 Max 内运行通过的结果；用户接手测试。

先用场景副本人工检查：

1. 在 A 中选择 Biped 手臂复制，在 B 中粘贴，检查姿势、当前帧关键帧和一次撤销。
2. 分别测试 Biped 全身（含 COM）、普通 Bone 和两者混合选择。
3. 连续粘贴同一份姿势两次，检查原有 Biped Copy Collections 保留、第二次不重复导入集合；一次撤销第二次粘贴时，第一次的结果应保留。
4. 让目标缺少一个同名对象或更改其父级，确认粘贴报错且场景没有被部分修改。
5. 在 Max 2021 → 2024、2024 → 2021 两个方向各测一次。

`tests/unit_tests/test_pose_clipboard.ms` 创建临时测试节点，检查 Bone 父子级、Biped 原生姿势、混合选择、重复粘贴和控制器保留。撤销用例在 `undo off` 调用环境下模拟窗口按钮，检查 Bone、Biped、混合粘贴的一次撤销/重做，以及失败时回滚姿势和关键帧、不撤掉之前的操作。不打开或保存正式场景；本轮尚未在 Max 内执行。

兼容目标为 Max 2021 和 2024；两版本双向传递 `.cpy` 以及真实角色的 IK、动画层行为，仍须用场景副本实测。测试通过状态以实际执行结果为准。
